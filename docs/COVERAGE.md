# CSS conformance coverage from WPT

The coverage artifact is generated by the static Web Platform Tests (WPT)
reftest harness. The source revision is the **exact commit** in
[tools/wpt/wpt-commit.txt](../tools/wpt/wpt-commit.txt), from
https://github.com/web-platform-tests/wpt (BSD-3-Clause). WPT content is
fetched by CI into an ignored sparse checkout; no WPT test corpus is committed.
See the root NOTICE for attribution.

## Scope and selection

The first pass scans reftests in css/css-flexbox, css/css-grid, css/css-box,
css/CSS2/box-display, css/CSS2/margin-padding-clear, css/CSS2/borders,
css/css-backgrounds, css/css-color, css/css-text, css/css-fonts,
css/css-position, css/css-overflow, css/css-sizing, css/css-values,
css/css-transforms (2D only), css/css-masking (clip-path only), and
css/selectors.

A candidate needs a link with rel=match or rel=mismatch. Non-reftest files
are not part of the denominator. The harness records an EXCLUDED row for
each candidate it cannot safely or faithfully evaluate: script elements,
testharness.js, reftest-wait, animation/transition, event handlers,
dynamic embedded resources, external requests, multiple reference links,
non-HTML references, unsupported local-resource formats or dependencies,
fonts outside WPT/fonts, unsupported CSS imports, 3D transforms, or masking
outside clip-path. The exact reason is preserved for every excluded candidate.
Reference documents are checked too. The filter deliberately errs on the
side of exclusion when a test needs unsupported runtime behavior.

References, local stylesheets and static resource URLs are resolved
**inside the checked-out WPT tree**. Stylesheets are inlined. Binary images
and fonts from WPT/fonts are converted to data: URIs; the renderer itself
never downloads resources. A reference or resource that cannot be supplied
safely is excluded rather than silently compared without its dependencies.
The rendering command is the release isr CLI, at 800 CSS px width and
--height-auto, with a fixed 800 CSS px layout viewport. Each test keeps its
own markup and CSS sizes; references receive identical rendering settings.

## Matching rule

Both images are rendered by isr independently. For rel=match, a PASS
requires identical dimensions and RGB pixels, except when the test declares
WPT fuzzy metadata. A fuzzy range constrains **both** the maximum absolute
RGB-channel difference at any pixel and the number of pixels with a nonzero
RGB difference. Both lower and upper limits are inclusive. For rel=mismatch,
PASS means the images do not satisfy that comparison rule. The harness
does not execute JavaScript, align images, mask antialiasing, or use a
separate browser. In particular, this is a pairwise isr reftest measure,
not independently verified browser parity.

WPT conventionally uses an 800-by-600 viewport for screenshots, whereas
the current isr CLI uses a fixed 800px-tall layout viewport and an
auto-height capture. This is a **method difference** that must be reviewed
before treating a pixel pass rate as full WPT conformance. It can introduce
false passes or failures for viewport-height-dependent tests. The first
CI result is a baseline, not a certification.

A 20-second limit applies to each test/reference pair. Renderer exit errors
are CRASH rows, timeouts are TIMEOUT rows, and pixel mismatches are FAIL rows.
None of those statuses makes the workflow fail. Selection/preparation or
report-generation errors and build/test errors do fail the workflow.

## Reading the artifact

The workflow uploads out/wpt/results.json and out/wpt/COVERAGE.md. Each
candidate reftest has exactly one row with its WPT path, area, status,
reason, and declared-property associations. The Markdown report groups
PASS, FAIL, CRASH, TIMEOUT and EXCLUDED counts by area.

The reported rate is:

    PASS / (PASS + FAIL + CRASH + TIMEOUT)

EXCLUDED candidates are visible but not counted in the denominator.
An area with no eligible tests is N/A, not 100%. A low pass rate cannot
be attributed to a particular CSS property without inspecting the files
and renders. The top failing-property table only counts CSS properties
textually declared in failing candidates; it is a prioritization hint,
not a proof of unsupported properties. CSS can fail because of layout,
cascading effects, font fallback, image support or a reference mismatch.

No coverage numbers are committed here. The first run's outcomes and the
unit tests are **NOT_RUN by this change's author**; use the CI artifact.

## First CI review

Check that the pinned checkout resolved to the expected commit, every
requested CSS area exists, and candidate counts/exclusion reasons are
plausible. Confirm that WPT/fonts requests were converted to data: URIs,
no resource was fetched during rendering, and script/animation-dependent
tests were rejected. Inspect a few simple green/red reftests, mismatch
cases, fuzzy cases and image-dimension failures. Review the number of
missing-resource exclusions, memory/runtime pressure, and viewport-height
sensitivity before comparing pass rates across revisions.

CI-only invocation (no WPT fetch by the runner):

    npm ci --ignore-scripts
    node --test tools/wpt/test.mjs
    cargo build --locked --release
    WPT_ROOT=.wpt ISR_BIN=target/release/isr node tools/wpt/index.mjs

The checkout must already exist at the pinned revision. The workflow is
the only component that fetches WPT.
